# ADR-0001: Why Fiqh Exists

## Status
Accepted

## Context
Fiqh is a Internal Developer Platform project focused on learning platform engineering and software engineering with Kubernetes, Terraform, GitOps, observability while keeping SRE practices and DORA metrices in mind through building a production-style cloud-native platform.

Fiqh is also intended to address a major engineering gap in the currrent skill set of the author,especially in:

- application architecture
- backend development
- system design
- production application internals
- engineering tradeoff analysis

## Decision
Fiqh should be production-style Internal Developer Platform focused on foundational platform engineering capabilities instead of relying on higher level platform abstration tools.

The project will prioritize:

- software engineering depth
- cloud-native infrastructure
- Kubernetes operations
- Terraform-based infrastructure management
- GitOps workflows
- observability and SRE practices
- security and policy enforcement
- developer self-service workflows
- documentation and architectural reasoning

The project will evolve incrementally over time through small, production-oriented improvements instead of attempting to build a complete platform immediately.

## Consequences

### Positive
- stronger software engineering capabilities
- deeper understanding of platform engineering principles
- practical experience operating cloud-native systems
- improved architectural and operational reasoning
- realistic experience integrating infrastructure and applications
- stronger portfolio and hiring signal for Platform Engineering and SRE roles
- better understanding of production tradeoffs and system complexity

### Negative
- large project scope
- steep learning curve
- higher implementation and maintenance complexity
- slower development compared to tutorial-style projects
- increased debugging and operational challenges
- risk of overengineering or losing focus
- cloud infrastructure costs for hosting and experimentation
